## 1. 概要と目的

本プロジェクトは、C言語を用いて**ソケット通信**と**マルチスレッド**を組み合わせた、銀行間の取引処理シミュレーションシステムです。

2つの異なる銀行（プロセス）間で発生する大量のトランザクションデータを並行処理し、データの整合性を保ちながら高速に送金・受金処理を行うことを目的としています。また、Raspberry Pi（組み込み環境）でのクロスコンパイルと動作検証も実施しました。

## 2. 使用技術

* **言語:** C言語
* **OS/環境:** Linux, Raspberry Pi
* **並行処理:** POSIX Threads (`pthread`) - マルチスレッドによる高速化
* **同期制御:** Mutex (`pthread_mutex`) / Condition Variables (`pthread_cond`) - 排他制御によるデータ整合性の確保
* **ネットワーク:** TCP/IP Socket (`socket`, `bind`, `listen`, `accept`) - プロセス間通信

# C言語授業課題集：並列処理とネットワークプログラミング

## プログラム詳細 (追加分)

### 銀行間通信プログラム (`./src/transaction.c`)

**目的:** 複数のスレッドによる口座間の並行トランザクション処理を通じて、マルチスレッド環境における**競合状態**と**排他制御（Mutexと条件変数）**の必要性を学ぶ。

#### データ構造 / 技術

* **並列処理:** `pthread` ライブラリを使用し、**10個のスレッド** (`th0`〜`th9`) を作成。
* **排他制御:**
    * `pthread_mutex_t mutex1`: 口座残高 (`acount`) へのアクセスを排他的に制御する。
    * `pthread_cond_t cvar`: **条件変数**。残高が不足している場合にスレッドを待機させ、入金後に再開させるシグナリングに使用する。
* **トランザクションデータ:** `trans.csv` から読み込んだ `from` (送金元)、`to` (送金先)、`amount` (金額) の配列。
* **初期状態の確認:** 全ての口座の初期残高は 10000。総残高はトランザクション前後で変化しないことを検証。

#### 主要な機能

| 関数名 | 概要 | 強調点 |
| :--- | :--- | :--- |
| `fun` (スレッド関数) | 各スレッドが並行してトランザクション処理を実行。送金元残高が不足した場合、`pthread_cond_wait` で待機し、デバッグメッセージ (`●`) を出力。送金処理後に `pthread_cond_signal` で他の待機スレッドに通知する。 | **デッドロック回避の条件変数** |
| `busy` | ダミーの計算を実行し、**意図的に処理時間を延ばす**ことでスレッド間の競合状態を発生させやすくする。 | **競合状態のシミュレーション** |
| `main` | トランザクションデータを読み込み、Mutexと条件変数を初期化し、10個のスレッドを起動・終了待ち合わせを行う。処理時間と最終残高の総和を出力し、**原子性**を検証する。 | **総残高の維持（原子性の確認）** |

### 5. Webサーバーの実装プログラム (`./src/webserv.c`)

**目的:** C言語とソケットプログラミング (`socket` API) を用いて、簡易的な**Webサーバー**を実装する。TCP接続の確立からHTTPリクエストの解析・応答までを行う。

#### データ構造 / 技術

* **通信プロトコル:** TCP/IP (IPv4)
* **API:** `sys/socket.h`, `netinet/in.h` などの標準的なソケットAPIを使用。
* **ポート:** ポート **80番** (`http`) を使用。
* **I/O処理:** `fdopen` を使用してソケットファイルディスクリプタをストリーム (`FILE*`) に変換し、`fgets`, `fprintf` でHTTPヘッダの読み書きを容易にしている。

#### 主要な機能

| 処理ステップ | 概要 | 強調点 |
| :--- | :--- | :--- |
| **初期化** | ソケットの作成、`SO_REUSEADDR` オプションの設定、アドレスの割り当て（`bind`）、接続待機（`listen`）。 | **ソケットの基本操作** |
| **接続受付** | `while(1)` ループ内で `accept` を実行し、クライアントからの接続要求を**次々に**受け付ける。 | **永続的なサービス提供** |
| **リクエスト解析** | 接続されたストリームからHTTPヘッダを一行ずつ読み込む。`GET` または `POST` メソッド、および `Content-Length` ヘッダを解析する。 | **HTTPヘッダの簡易解析** |
| **`GET` 応答処理** | クライアントに **200 OK** を返し、簡単なフォームを含む **HTMLコンテンツ**を出力する。 | **HTMLフォームの提供** |
| **`POST` 応答処理** | `Content-Length` に基づきボディ部分を読み取り（データの受け取り）、**200 OK** の応答（`"OK"\r\n`）を返す。 | **データ送信の受付処理** |
